# MagicBox 平台策略与限制

## 1. 平台优先级

当前版本的平台策略是：

1. Android 独立 App 体验优先
2. iOS 保持代码结构兼容
3. 微信小程序保留受限能力与管理能力

## 2. 为什么改成 Android 优先

MagicBox 的核心价值之一，是把各种外部入口集中收藏并直接打开。

这件事在微信个人主体小程序内存在天然边界：

- 外部网页能力受限
- 域名配置前置
- 任意第三方网站不可完全自由直开
- Deep Link / 外部应用跳转能力不稳定

因此，当前版本不再把“微信内任意网址都能稳定打开”当成主承诺。

## 3. Android 策略

Android 是当前最适合承载 v1 核心体验的平台。

### 3.1 网页

- 优先在应用内浏览页打开
- 必要时可切系统能力兜底

### 3.2 App Deep Link

- 尝试调用宿主可用的打开能力
- 失败时复制链接并提示

### 3.3 小程序链接

- 优先识别 `appId + path`
- 有能力时尝试拉起
- 无法拉起时保留提示和复制信息

## 4. iOS 策略

iOS 现阶段的策略不是抢先覆盖所有能力，而是保证结构兼容：

- 页面结构一致
- 数据模型一致
- 核心管理流程不被破坏

也就是说，iOS 当前更重视“能管理、能维护、能继续演进”，而不是保证每一种外部打开都与 Android 完全等价。

## 5. 微信小程序策略

微信小程序当前定位为：

- 收藏数据管理端
- 结构展示端
- 能力受限提示端

不作为“任意外站直开”的主要交付平台。

### 5.1 保留能力

- 浏览和管理收藏
- 添加 / 编辑
- 文件夹组织
- 本地 JSON 导入导出
- 固定页配置

### 5.2 受限能力

- 任意外部网页稳定直开
- 任意 App Deep Link 稳定拉起
- 未预先配置域名的网站预览

## 6. 固定页策略

Fixed Page 当前仍保持“应用内打开”的产品语义，但其实现受到宿主容器能力影响。

设计原则是：

- 优先内部查看
- 不让用户进入死路
- 当 Dock 与 WebView 同层有冲突时，至少提供清晰返回路径

## 7. 当前版本边界

以下内容明确不纳入当前主承诺：

- 云端协同同步
- 团队级共享空间
- 微信个人主体下的任意网址免配置打开
- 所有 Deep Link 的跨平台一致性

## 8. 版本判断标准

只要以下体验稳定，当前版本就算成立：

- 用户可以把常用入口整理成桌面
- 图标可以拖拽、归类、编辑、删除
- 网页链接可在合适的平台内顺畅打开
- 固定页可作为常驻入口使用
- 数据可以本地导入导出与恢复
